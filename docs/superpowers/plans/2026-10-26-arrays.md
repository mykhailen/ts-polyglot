# Arrays Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Marshal counted sequences between TypeScript and C, C++ and Rust: `Vec<T>`, slices and
`[T; N]`; `std::vector<T>` and `std::array<T, N>`; C arrays as struct fields and as `const T xs[]`
parameters paired with a length; bytes as `Uint8Array`; nested to any depth, in both directions.

**Architecture:**
- The model (`signatures.ts`) already has `array`; it gains `max` on strings (a C `char[N]`),
  `Param.length` (the C length parameter), `visibleParams` (the parameters JavaScript passes), and
  `parseIntegerLiteral` for sizes. `supported` accepts arrays of supported, non-reference elements.
- The walkers record the forms: sizes from literals or same-file constants, `char[N]` as a bounded
  string, the C length rule, `std::vector`/`std::array`, `Vec`/slices/arrays. Everything a language
  can't carry becomes `unknown`.
- One ABI kind, `array` (`ts_polyglot_array { void* ptr; size_t len; release }`), with the element's
  `AbiType`. The glue (`marshal.ts`, `glue.ts`) gets one reader and maker per distinct array type,
  named by `abiId`, a bytes path for unsigned 8-bit elements, prototypes before definitions, and
  cleanup through elements.
- The C bridge grows what C++ has: a prelude with owning helpers, mirrors for structs holding arrays
  or `char[N]`, shims (with an error slot) for functions that need them, and temporaries for
  sequences whose elements need converting. The C++ bridge converts std containers through a static
  template family and C-style arrays through the loop generator it shares with C
  (`c-family-bridge.ts`). The Rust bridge gets three generic helpers and recursive conversions.
- `jsType` prints `readonly T[]` and tuples in parameter position; `declarations.ts` prints
  `visibleParams`.

**Tech Stack:** TypeScript 7.1 beta, Node 22.18+ (`node:test`, type stripping), web-tree-sitter
0.27.1 with the pinned grammars, Node-API (`node-api-headers` 1.9.0), MSVC / gcc / clang, rustc.

**Spec:** `docs/superpowers/specs/2026-10-26-arrays-design.md`. Its "What crosses, and how", "The C
length rule", "The ABI" and "The three layers" sections are the rules; this plan names the code and
the tests that pin them. Part two's spec (`2026-10-25-types-and-marshaling-design.md`) still governs
everything else.

the code:

**Interfaces:**
- Produces, in `signatures.ts`:

```ts
| { kind: "string"; nullable: boolean; max?: number }   // max: a bound in UTF-8 bytes (a C char[N] holds N - 1)
export interface Param { name: string; nameStart?: number; type: NativeType; length?: { name: string; type: NativeType } }
/** The parameters JavaScript passes: every one that isn't another's `length`. */
export function visibleParams(fn: NativeFunction): Param[];
/** An integer literal as C or Rust spells one, or undefined: zero, a name, an expression, a float. */
export function parseIntegerLiteral(text: string, language: "c" | "rust"): number | undefined;
```
  `supported`: `array` → `supported(of)` and `of.kind` is neither `reference` nor `void`.
  `structsInDependencyOrder`: a field's struct is found through any depth of `reference` and `array`.
  `parseIntegerLiteral`: trims; C: optional suffix `[uUlL]+`, `0x`/`0X` hex, a leading `0` octal,
  else decimal; Rust: `_` separators dropped, suffix `(u|i)(8|16|32|64|128|size)`, `0x`, `0o`, `0b`,
  else decimal; the result must be a safe integer ≥ 1.
- Produces, in `language.ts`:

```ts
| { kind: "string"; max?: number }                  // the glue rejects more bytes than max, and any NUL
| { kind: "array"; of: AbiType; length?: number }   // c is "ts_polyglot_array"
/** A C identifier fragment unique to an AbiType, for the glue's helper names. */
export function abiId(abi: AbiType): string;
```
  `abiId`: `int_` or `float_` plus `c` sanitized (`[^A-Za-z0-9_]` → `_`): `int_long`,
  `int_unsigned_long`, `int_int64_t`, `float_double`; `bool`, `char`, `cstring`, `void`; `string`,
  or `string_15` with a bound; `struct_` plus `c` sanitized (`struct_struct_Point`,
  `struct_ts_polyglot_Point`); `array_` plus the length and `_` when fixed, plus the element's id
  (`array_int_int32_t`, `array_3_float_float`, `array_array_string`).

### Task 2: The C-family walker: sizes, constants, fields, templates and the length rule

**Files:**
- Modify: `packages/ts-polyglot/src/languages/c-family.ts`
- Test: `packages/ts-polyglot/test/c.test.ts`, `packages/ts-polyglot/test/cpp.test.ts`

**Interfaces:**
- Consumes: `parseIntegerLiteral(text, "c")`, `Param.length`, `string.max` (Task 1).
- Produces: `cFamilyModule(root, source, dialect)` records, besides what it does today:
  - sizes: `number_literal` through `parseIntegerLiteral`; an `identifier` through a `Constants`
    collection the first pass fills from `preproc_def` (`name`, `value: preproc_arg`; the text
    trimmed, one pair of surrounding parentheses stripped) and from a `declaration` with a `const`
    or `constexpr` qualifier whose `init_declarator` has a `number_literal` value (or one inside a
    `parenthesized_expression`), keyed and resolved like `Structs` (file scope and namespaces,
    innermost out); any other size → the whole type is `unknown`;
  - a nested array's spelling lists its dimensions outer first: `int grid[2][3]` is
    `array(2, array(3, int))` with spelling `int[2][3]`;
  - fields: an unsized array → `unknown`; `char x[N]` (element spelling exactly `char`, however
    deep: `char names[4][8]` is `array(4, string max 7)`) → `{ kind: "string", nullable: false, max:
    N - 1 }`; the `const char*` rule applies to array elements (`const char* tags[3]` is an array of
    nullable strings);
  - parameters: a sized array `const T v[N]` is `array` with `length` and no `Param.length`; a sized
    `const char v[N]` is a bounded string; an unsized array pairs by the C length rule: the size
    naming an integer parameter (C99, either side), else the first integer parameter after it with
    only unsized arrays in between, all of which share it; an unsized `char` array paired is
    `{ kind: "string", nullable: false }` (counted); no pairing, or an element type that isn't
    `const` (`hasConst(declaration)`) and isn't a nullable string → `unknown`; a paired array's
    `Param.length` is `{ name, type }` of the length parameter, which stays in `params`;
  - C++ templates in `namedType()`: a `qualified_identifier` with scope `std` and a `template_type`
    named `vector` with one `type_descriptor` argument → `array` of that type (the descriptor's
    `type` and abstract declarators through `declared()`); `array` with a `type_descriptor` and a
    size → `array` with `length`; an element that is itself a C-style array → `unknown`; every other
    template, and an unqualified `vector<T>`, stays `unknown`.

/** `error`, or `ts_polyglot_error` when a parameter is named `error`. */
export function slotName(fn: NativeFunction): string;
/** `int name[2][3]` for array(2, array(3, int)): the element's C spelling, the name, the dimensions outer first. */
export function cDeclarator(type: NativeType, name: string): string;
/** Statements copying ABI storage `src` (an lvalue) into native storage `dst`: loops for fixed arrays, memcpy and a NUL for a bounded string, `from_<Name>` for a mirrored struct, assignment otherwise. `element(type, expr)` is the dialect's expression for converting one struct or string element; `depth` numbers the loop variables i0, i1, …, which the caller declares as `size_t`. */

export function copyOut(abi: AbiType, type: NativeType, dst: string, src: string, dialect: Dialect, depth?: number): string[];

```ts
export function cMirrors(module: NativeModule): string[];   // typedef, from_<Name>, to_<Name> per struct that needsMirror, in dependency order

```
  The shim: `static <ret.c> ts_polyglot__shim_<name>(<abi.c> <p>, …, ts_polyglot_string* <slot>) {`;
  locals first: `<ret.c> ts_polyglot_out = {0};` (unless void), `<user result spelling>
  ts_polyglot_result;` when the result is a mirrored struct, one temporary per parameter whose
  elements need converting (`<cDeclarator(elem, "ts_polyglot_tmp_<p>")>` for a fixed array, `<elem
  c>* ts_polyglot_tmp_<p> = NULL;` for a sequence), `size_t i0, …;` as `loopDepth` needs; then the
  checks, each `{ *<slot> = ts_polyglot__own_text("<message>"); goto done; }`: for every array
  sharing a length with an earlier one, `if (b.len != a.len)` → `"<fn>(): b must have as many
  elements as a"`; for a length type that is signed or narrower than 64 bits, `if (a.len >
  (size_t)<max macro>)` → `"<fn>(): a has more elements than <type spelling> holds"`; a sequence
  temporary: `ts_polyglot_tmp_p = (<elem c>*)malloc((p.len ? p.len : 1) * sizeof(<elem c>));` then
  `if (!ts_polyglot_tmp_p)` → `"<fn>(): can't allocate p"`; then the fills (`copyIn` with `dst`
  `ts_polyglot_tmp_p[i0]` under a loop over `p.len`, or the fixed `copyIn` into the array temporary);
  then the call, `ts_polyglot_out = ` or `ts_polyglot_result = ` or bare for void, with arguments:
  a length parameter → `(<its c>)<first array sharing it>.len`; a sequence or fixed array of plain
  elements → `(<elem c> const*)<p>.ptr`; of converting elements → `ts_polyglot_tmp_<p>`; a bounded
  or counted string → `<p>.ptr` (and the counted form's length through its length parameter); a
  mirrored struct → `ts_polyglot__from_<Name>(&<p>)`; else `<p>`; then `ts_polyglot_out =
  ts_polyglot__to_<Name>(&ts_polyglot_result);` for a mirrored result; `done:` (only when a `goto`
  exists), `free(ts_polyglot_tmp_<p>);` per sequence temporary, `return ts_polyglot_out;`.

unsafe extern "C" fn ts_polyglot_release_list<T>(ptr: *mut std::ffi::c_void, len: usize) {
